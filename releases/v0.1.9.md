# AI Fence CLI v0.1.9 Preview

Verified updates now request older managed Codex desktop connections to reconnect
when idle by default. Linux/WSL terminal automatic-update checks also service
registered desktop installations, so replacing the terminal CLI no longer leaves
an independent managed desktop payload behind. The same-server and channel
boundaries, existing update policy, credential owner and history store are retained.

Use `ai-fence-cli codex-desktop update --no-reconnect` for a one-off opt-out, or
set `AI_FENCE_CODEX_RECONNECT=off`. The explicit flag overrides the environment,
which overrides the saved setup policy (`setup --reconnect off`). Updating remains
available when reconnect is disabled. Explicit `update --reconnect` and
`reconnect --apply` remain available.

The new `codex-desktop reconnect` command previews affected connections.
`--apply` arms one installation-scoped request; `--status` reports results and
saved thread IDs; `--cancel` cancels requests not yet acknowledged. Active turns,
authentication, pending requests and approvals are allowed to finish. Busy
requests expire rather than force-interrupting work. Concurrent launches,
changed settings and modified release files cannot redirect the operation to
another profile or process.

Reconnect does not restart WSL, the desktop application or the admission service,
and creates no background monitor or extra full Codex session. Native Windows
tasks and ordinary CLI/tmux sessions remain available. No checkpoint is restored,
history rewritten, credential store merged or workspace deleted.

Codex desktop may need its saved chats reopened after the backend reconnects.
Thread identities are retained for that purpose; automatic restoration of desktop
tabs is not advertised. Adapters already running an older release require one
manual reconnect to gain cooperative control. Older custom install roots can
register for terminal updates with `codex-desktop --install-root PATH register`.

Desktop integration requires Linux/WSL, Python 3.11+ and native stdio transport.
Launch updates target Linux x86_64. Shared native subscription auth requires file
credential storage and the supported external-token API. This update does not
enable upstream subscription `response.steer`. The macOS ARM preview is ad-hoc
signed and requires macOS 12+; it is not notarized. Linux x86_64 requires glibc
2.34 or newer. Checksums verify bytes and are not a publisher signature.

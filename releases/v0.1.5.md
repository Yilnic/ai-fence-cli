## AI Fence CLI v0.1.5 Preview

### Codex auth-pool startup

Newly rented Codex credentials are installed in the managed `CODEX_HOME` before
the native CLI starts. For auth-pool runs, the launcher uses `--no-daemon` when
the installed Codex supports it. This prevents an existing background daemon
from showing a stale login chooser after a previous rental ended.

Concurrent AI Fence launches on one machine continue to share one active pool
rental. Codex refreshes the native credential while running; AI Fence returns
the updated credential after the final local session exits. No separate
ChatGPT login is required for a valid rented credential. The deprecated
`preferred_auth_method` setting is no longer written to Codex configuration.

The fix was checked with Codex 0.157.1 on Linux: a new rental opened the
interactive prompt without a login chooser, and the temporary credential was
removed after exit. Native Windows and macOS smoke tests and account-feature
entitlements were not checked.

immutable; checksums identify content, not a publisher signature. The macOS
preview is ad-hoc signed, without Developer ID signing or notarization.

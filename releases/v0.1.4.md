## AI Fence CLI v0.1.4 Preview

This preview includes the Lite alias support and native subscription startup
fixes described below, plus improved recovery after a rejected rental request and native conversation
compatibility fixes.

### Native subscription startup

The launcher validates the requested Codex home before renting subscription
credentials. An invalid home is rejected without creating a rental. This fixes
a startup failure in v0.1.1 that could leave a rental outstanding. It does not
retroactively reconcile rentals left by older executables.

### Rental recovery and connected Codex compatibility

When the service definitively rejects a rental request before creating a rental,
the launcher removes only that attempt's pending recovery marker. Unknown
conflicts and transport failures retain recovery information. Existing native
authentication state and the home lock remain intact.

With the updated AI Fence service, native subscription requests accept Codex
inline message identifiers and preserve supported hosted web-search definitions,
search history, sources, and citations. These service-side fixes require an
updated server; upgrading the CLI alone does not update a self-hosted server.
Compatibility regressions are covered with mock-provider tests, not a claim of
successful live-provider inference for this release.

### Native conversation continuation

The updated service preserves Codex assistant message phases in continuation
history and accepts supported native tool catalogues above the owner-only
128-entry limit. Request-size limits, tool-structure validation, model binding,
and budget admission still apply. These are service-side compatibility fixes;
self-hosted installations need the updated server as well as the CLI.

### Reversible aliases in Lite

Lite can now load explicit original-to-alias mappings and additional regex rules
from a project-local `.ai-fence.yml`, `.ai-fence.yaml`, or `.ai-fence.toml` file.
No AI Fence account or Pro subscription is required in standalone mode.

```yaml
redaction:
  aliases:
    - original: feature/apple
      alias: feature-a
    - original: feature/berlin
      alias: feature-b
```

Run `ai-fence-cli run --standalone --agent codex` (or use the standalone Claude
launcher). The provider sees the aliases; supported response text and tool
arguments restore the original names. Follow-up requests protect the names again.
The nearest configuration between the working directory and Git root wins,
including worktrees; outside a repository only the working directory is checked.
Restart the launcher after configuration changes. Keep files containing sensitive
originals private.

- Conflicting aliases and invalid local regex rules are rejected at startup.
- Literal input that already equals an alias stays distinct from the mapped name.
- Streaming respects alias boundaries and restores only one substitution layer.
- Structured tool arguments are buffered until valid JSON is available, preserving
  keys and escaping restored values. Parallel Chat Completions tool calls are
  buffered separately.

Original matching is case-sensitive; alias restoration is ASCII case-insensitive.
Letters, digits, underscores and hyphens form identifier boundaries. Aliases
must start with a letter and use 3–128 ASCII letters, digits, `_`, `-`, `.`, or `/`;
reserved generated-placeholder names and overlapping mappings are rejected.
Masking policies still take precedence over returning original values.

### Downloads and verification

- [Linux x86_64](https://github.com/Yilnic/ai-fence-cli/releases/download/v0.1.4/ai-fence-cli-linux-x86_64)
- [Windows x86_64](https://github.com/Yilnic/ai-fence-cli/releases/download/v0.1.4/ai-fence-cli-windows-x86_64.exe)
- [macOS Apple Silicon](https://github.com/Yilnic/ai-fence-cli/releases/download/v0.1.4/ai-fence-cli-macos-aarch64)
- [SHA256SUMS](https://github.com/Yilnic/ai-fence-cli/releases/download/v0.1.4/SHA256SUMS)

Verify the executable against SHA256SUMS before running it. Release assets are
immutable; the installer follows the selected published version independently
of later backend deployments. Checksums identify content, not a publisher signature.

This remains a preview. macOS requires Apple Silicon and macOS 12 or later and
uses ad-hoc signing, without Developer ID signing or notarization. Publication
checks Linux startup and all three artifact hashes; native Windows/macOS smoke
tests and real-provider compatibility remain separate checks.

The official executable contains the separately distributed processing engine;
the public MIT-licensed workspace contains the launcher, transport, contracts,
and metadata and does not build the complete executable on its own.

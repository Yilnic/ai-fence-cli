# AI Fence CLI v0.1.14

Fix Codex desktop WSL connections timing out after Btrfs storage is remounted.
The integration now recognizes the existing history, credential and workspace
directories by their persistent subvolume UUID and inode when Linux assigns a
different device number. Changed paths, replacement directories, different
subvolumes and changed credential accounts remain rejected.

Registered terminal updates and adapter upgrades use the same identity check.
Existing credential metadata can acquire a persistent UUID when its original
device/inode still matches, or when the saved history UUID proves that the
unchanged credential inode remains on that same subvolume.

If an older adapter already times out before checking for updates, update the
terminal CLI on the installation's existing channel, then run its
`codex-desktop update-registered --source-base-url <configured-source>` command.
Reconnect the Ubuntu connection in Codex after the adapter update completes.
Conversation history, login files and project contents are retained.

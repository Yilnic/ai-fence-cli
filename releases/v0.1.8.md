## AI Fence CLI v0.1.8 Preview

Persistent named writable Btrfs workspaces make parallel local agents practical.
`fw create feature-a` creates a workspace once; `fws feature-a` switches your
current directory to it. `fw` means Fence workspace; `fws` means Fence workspace
switch. Management commands and workspace names no longer compete: `fws ls`
enters a workspace named `ls`, while `fw ls` lists workspaces.

Official setup/install-self initializes Bash/zsh, Git Bash and PowerShell helpers;
CMD uses installed command files. Windows workspace commands bridge to an
existing WSL Linux installation, and native Windows commands remain available.
`install-self --no-shell-init` leaves profiles untouched. PowerShell workspace
initialization assigns its built-in `fw` shorthand to Fence; use `Format-Wide`
for the original PowerShell command.

Workspaces retain Git, uncommitted and untracked changes across launches.
CLI and Codex desktop share workspace identity, native thread registration and
process leases. Missing workspaces require explicit recovery. Removal previews
protect active, pinned, dirty and chat-linked work; recovery creates another
workspace instead of restoring over later changes or conversation history.

Automatic read-only checkpoints now default to **off**. Explicit checkpoint
commands remain opt-in; `AI_FENCE_SNAPSHOTS=off` remains a hard disable.
Account/profile selection, native auth and existing history stores are unchanged
by workspace selection. See [the workspace guide](../WORKSPACES.md).

Writable snapshots require Linux/WSL, a user-owned Btrfs subvolume root and a
store on the same filesystem. Nested mounts/subvolumes, submodules and
shared/external Git metadata are rejected. Windows shells use WSL UNC paths;
CMD switches with `pushd` (return with `popd`). This does not enable Btrfs on NTFS.

Validation includes real Bash, zsh, Git Bash, CMD, Windows PowerShell 5.1 and
PowerShell 7, plus native Codex 0.162.1 with isolated fake state and no inference.
Kernel Btrfs clone/delete/recovery operations are fixture-tested. Windows desktop
UI discovery, real OAuth refresh and provider inference remain separate checks.
Existing app-servers keep their runtime until deliberately updated/reconnected.

Official Codex desktop/WSL setup now defaults to verified automatic proxy
updates on future app-server launches, normally once daily. Immutable releases,
checksums, bounded downloads, failure backoff and nonblocking update locks keep
the working installation available. Activation preserves the complete selected
settings, history/account identities, checkpoint policy and existing admission
prefix. Running chats retain their own release and proxy endpoint. `codex-desktop
update --check-only`, `update` and `doctor` expose the selected/running versions;
rollback disables automatic reactivation until explicitly re-enabled. Launch
updates currently support Linux x86_64 only. No background service or timer is
installed. Custom pinned installations require an explicit setup migration.

Desktop shared-native authentication selects one credential owner with
`--auth-home` while retaining conversations in `--state-home`. Native Codex owns
login and refresh; the history process receives ephemeral access tokens through
the installed native external-token API. Revoked profile credentials are
preserved rather than reused or overwritten. Account switches fail explicitly.
Shared mode currently requires desktop stdio, file credential storage and native
external-token API support; profile auth remains available for other modes.
Session-only native routing keeps that credential owner and history store;
doctor identifies the unfenced launch explicitly.

The new native checks use Codex 0.163.0, synthetic accounts and a local HTTPS
account/release fixture. They cover login/logout/reconnect, retained synthetic
history, exact credential ownership, and a real official CLI update while an
older connection stays live. They do not validate real OAuth refresh, provider
inference or Windows desktop UI discovery. Upstream subscription
`response.steer` remains disabled; a proxy update alone does not enable it.
See [the desktop guide](../CODEX_DESKTOP_WSL.md).
